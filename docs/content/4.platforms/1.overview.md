title: Overview
description: Which OS credential store each platform uses, and the limits that differ between them.
---

The plugin uses the native store of each platform through the official
[`keyring-core`](https://crates.io/crates/keyring-core) backend crates. There is no in-memory or file
fallback: if the store is missing, calls fail.

| Platform | Store | Crate |
|----------|-------|-------|
| [macOS](/platforms/macos) | Login Keychain | `apple-native-keyring-store` (`keychain`) |
| [Windows](/platforms/windows) | Credential Manager | `windows-native-keyring-store` |
| [Linux](/platforms/linux) | Secret Service over D-Bus (GNOME Keyring, KWallet, KeePassXC, …) | `dbus-secret-service-keyring-store` (`crypto-rust`) |
| [Android](/platforms/android) | Android Keystore + SharedPreferences | `android-native-keyring-store` |
| [iOS](/platforms/ios) | Data-protection Keychain | `apple-native-keyring-store` (`protected`) |

The store starts on the first call. If it fails to start (e.g. no D-Bus session yet), the error is
not cached: the next call after a 2-second pause tries again.

## Entries

Every entry has a **service** (your app identifier or the name set with `Builder::service`) and an
**account**: the name you pass to the [password commands](/guides/passwords), or a hashed `kp:v1:…`
name for [session records](/guides/sessions#how-names-become-entries). Byte values are stored as
Base64 text.

## Differences

| | macOS | Windows | Linux | Android | iOS |
|-|-------|---------|-------|---------|-----|
| Size limit | — | 2560 bytes per secret, see [Windows](/platforms/windows) | — | — | — |
| Can prompt the user | yes (access) | no | yes (unlock) | no | with `RequireUserPresence` |
| Needs extra setup | no | no | a running Secret Service | no | a signed app |
| Locked device | — | — | locked collection prompts | — | `KeychainLocked`, see [iOS](/platforms/ios) |

Test on every platform you ship: the [example app](https://github.com/s00d/tauri-plugin-keyring-store/tree/main/examples/tauri-app)
runs on all of them.
